# Theme

One file is the source of colour: `themes/ikigai/palette.json`. Everything else is
rendered from it and committed next to it. Never hand-edit an output.

## Palette

Material 3 neutrals seeded from the wallpaper's orange, so the greys are near-black and
warm. The accent from its blue. An ANSI 16 built in OKLCH. `scripts/theme-palette.py`
makes a `palette.json` from seed colours; `scripts/theme-build.py themes/<name>` renders it
into:

| Output | Read by |
|---|---|
| `shell.json` | the shell, via `~/.local/state/ikigai/shell-theme.json`; the greeter and lock from `/run/current-system/sw/share/ikigai/theme` |
| `cosmic/` | cosmic-comp's window chrome, every libcosmic app. Built `CosmicTheme.Dark/v2` files, generated by `tools/cosmic-theme-gen` from `builder.ron` |
| `gtk/gtk.css` | GTK 3 and 4 through adw-gtk3, Qt through its gtk3 platform theme |
| `ghostty/`, `btop/`, `vicinae/` | those apps |
| `cursors/` | Bibata Modern recoloured, see below |

Every terminal tool without its own file follows the terminal's ANSI colours. Two
exceptions: Zed is Tokyo Night from its registry, and starship carries a hard-coded Tokyo
Night palette in `config/starship/starship.toml`.

The theme package (`nix/pkgs/ikigai-theme.nix`) puts each output where its consumer
reads it:

| Path | |
|---|---|
| `share/ikigai/theme/{shell.json,wallpaper.jpg}` | the greeter and lock, one fixed path |
| `share/ikigai/themes/<name>/` | the per-app files, which the home module links into `~/.config` and `~/.local/share` |
| `share/backgrounds/ikigai/<name>.jpg` | what `CosmicBackground` points at |
| `share/cosmic/` | the COSMIC theme, system layer |
| `share/icons/Ikigai/` | the cursors, rasterised at build |

`ikigai.theme` in the flake picks the name; `themes/<name>` is built and the system
profile merges it in. `just theme` only rebuilds the files from `palette.json`; the box
picks them up at the next rebuild. A user-layer COSMIC theme would shadow the system one,
so the home module moves one it finds to `~/.local/state/ikigai/backup/` at switch.

## Cursors

Bibata Modern's SVG sources, vendored (`cursors/bibata`, GPL-3, `scripts/vendor-cursors.sh`).
`theme-build.py` swaps their three placeholder colours for the theme's: body and outline
from the surface pair, the wait pie and corners from the ANSI colours, badges from the
accents. cosmic-comp renders the SVGs at any scale. GTK, Qt and Chromium want Xcursor
files, so the theme package runs `scripts/cursor-raster.py` at build, 24 to 96 px, into
`share/icons/Ikigai`. The session and greeter put `/run/current-system/sw/share/icons` on
`XCURSOR_PATH`; the home module sets the same cursor for GTK.

## Icons

Phosphor everywhere.

- `shell/Icons.qml`: the glyph table, generated from Phosphor's web font by `scripts/vendor-phosphor.sh`. The font itself is `nix/pkgs/phosphor-font.nix`, fetched from the same release; keep the two at one version.
- `icons/Ikigai`: a symbolic icon theme from Phosphor's SVGs, named per `icons/phosphor.map`, built by `scripts/vendor-icon-theme.sh`, packaged as `ikigai-icons`. COSMIC's window buttons, cosmic-settings, GTK header bars and Qt pick it up.
- `shell/icons/brand`: hand-drawn marks for Ghostty, Zen and Zed. `shell/Apps.qml` maps app ids to Phosphor's logos where it has one.
- `config/fastfetch/logo.txt`: the wallpaper as text, `scripts/logo-ascii.py`.

## A second theme

1. `scripts/theme-palette.py` with new seeds, or a hand-written `palette.json`, plus a wallpaper, in `themes/<name>/`.
2. `tools/cosmic-theme-gen` for the COSMIC files, `theme-build.py` for the rest.
3. `ikigai.theme = "<name>";` in the flake, then rebuild.

The home module follows the name for Ghostty's theme and the btop and Vicinae theme
files it links. The seeded `btop.conf` and Vicinae `settings.json` still name `ikigai`,
and so do Zed and starship. That is the open part.

## COSMIC internals

Verified against COSMIC 1.7.0 and the libcosmic rev cosmic-settings pins (`2a73fbc`).
nixpkgs ships cosmic-settings at epoch 1.6.0; re-verify at the next bump.

- The theme is `CosmicTheme.Dark/v2`, 37 derived keys. `.Builder` is inert outside cosmic-settings. Settings' import fails silently on any RON error, which is why `cosmic-theme-gen` exists. Upstream's shipped theme lacks `list_button`, so every component logged "Failed to load the theme" at login; ours has it.
- Fonts and icon theme: `CosmicTk/v1`. Wallpaper: `CosmicBackground/v1/{all,same-on-all}`. Upstream's `all` has a RON bug (`#true`); don't copy it.
- The greeter reads the same system theme layer. Its wallpaper comes from a user's cosmic-bg state, so it matches after first login.

revision is `95d891e1bbe79f3df81f971986f343c8907c05b0`; the compositor fork is

## Findings

Except for the isolated restoration reproduction, these findings come from tracing
the code and its call sites. They have not all been reproduced interactively.
Priorities indicate urgency, not implementation order within a release.

### [P1] Avoid re-entering the pointer mutex during autoscroll

Location: [cosmic-comp/src/shell/grabs/autoscroll.rs:204](https://github.com/runitbackdev/cosmic-comp/blob/b56fc012ecbaa5c5c1976c45671a87a813abf858/src/shell/grabs/autoscroll.rs#L204).
With autoscroll and Xwayland pointer-event sharing enabled, an ordinary middle-click
can deadlock the compositor. Smithay invokes the grab while holding its pointer
mutex; `deliver_press()` calls the Xwayland notification function, which calls
`pointer.current_focus()` and acquires that same mutex. Move the notification
outside the grab callback or pass the required focus state into it. The Xwayland
sharing setting is a condition of this finding; it is not enabled by default.

### [P2] Preserve button grabs when cancelling autoscroll

Location: [cosmic-comp/src/shell/grabs/autoscroll.rs:275](https://github.com/runitbackdev/cosmic-comp/blob/b56fc012ecbaa5c5c1976c45671a87a813abf858/src/shell/grabs/autoscroll.rs#L275).
Pressing another button while scrolling forwards that press, then removes the grab
without establishing the normal click grab. Pointer focus can subsequently move
before release. The later middle-button release also escapes even though its press
was suppressed. Cancellation needs to preserve the remaining button sequence and
implicit grab.

### [P2] Retain saved tab directories when loading the session

Location: [shell/Restore.qml](../shell/Restore.qml), lines 83 and 260 at the reviewed
revision. Restoration reads `saved.tabs`, but the loader constructs `saved` with
only `windows`. The directory queue stays empty and additional Ghostty tabs never
reopen. An isolated execution of the actual loading expression with two saved
directories reproduced the loss. Preserve and validate `tabs` when loading.

### [P2] Animate the card background with its content and input region

Location: [shell/Popouts.qml](../shell/Popouts.qml), line 22. The cascading-menu
change feeds final `baseWidth` and `baseHeight` values to the background blob while
the frame and input mask still animate. Opening, closing, or changing cards makes
the background jump independently of its contents. During transitions, parts of
the visible card can lie outside its input region. Drive these from consistent
animated geometry, including the separate submenu panels.

### [P2] Identify saved Wi-Fi connections by UUID and SSID

Location: [shell/Network.qml](../shell/Network.qml), lines 66 and 163. Saved
connections are indexed by profile name, then compared with the network's SSID.
A connection renamed through Settings is treated as unsaved, causing another
password prompt and duplicate profile creation. Forget also targets the SSID as a
profile name. Store the profile UUID separately from its display name and SSID.

### [P2] Aggregate volume-card state across screens

Location: [shell/Bar.qml](../shell/Bar.qml), line 94. Every rail independently binds
the same global `Osd.suppressed` property. One card closing can overwrite another
card's open state when moving between monitors, showing the OSD over an already
open volume control. Suppression should derive from whether any volume card is open.

### [P2] Show task-manager failures after the first sample

Location: [shell/Monitor.qml](../shell/Monitor.qml), line 280. If the monitor daemon
fails after producing data, `error` is set but `sample` remains populated. The error
message stays hidden and the last readings remain displayed as though live. Show a
disconnected state and mark retained readings as stale.

## Fork policy and maintenance

**Maintain the patches downstream. No upstream submissions are planned.** The
maintainer has identified the upstream projects as disallowing AI contributions
and does not want AI-assisted work forwarded to them. Any reconsideration requires
the maintainer's own deep review, an explicit decision to revisit submission, and
compliance with the receiving project's contribution policy. Human review does not
erase AI provenance. This policy supersedes the audit's initial suggestion to
prepare some fixes for upstream submission.

The purpose of cleanup is to make Ikigai's dependencies understandable, testable,
and maintainable. For each patch, record its purpose, provenance, behavioural
tests, compatibility assumptions, and maintenance cost. Keep correctness fixes
separate from product policy. Track upstream changes so patches can be removed
when independently developed upstream fixes cover the same need. Do not prepare
or submit upstream contributions without an explicit new decision.

  616 lines and removes 31 across eight files. Test button combinations,
  constrained pointers, Xwayland, cancellation, and cursor behaviour before
  extending it.

The portal's documented stream-teardown fix remains unimplemented in the fork.
Existing technical notes in [upstream.md](upstream.md) remain useful as a record of
dependencies and workarounds; they are not a submission roadmap.

## Portable shell, desktop, and OS

Ikigai already has a recognizable visual identity and substantial desktop
functionality. Its weakest boundaries are integration ownership, failure handling,
and validation across configurations. The proposed split is two installable
products built from three layers:

| Layer | Responsibility |
|---|---|
| Ikigai Shell | QML, visual components, interaction, and service interfaces |
| Ikigai Desktop | Compositor integration, session lifecycle, portals, and authentication agents |
| Ikigai OS | NixOS integration, installer, updates, hardware policy, and curated applications |

The portable product provides the shell with the desktop integration needed for a
supported Linux session. The OS product composes that desktop with NixOS. Installing
the shell should not require adopting Docker, zsh configuration, editor preferences,
or system tuning.

The parked `fedora` branch at `4ffebd942561238d467f122683dca03c7e6c37df` is a useful
starting point. It contains a prefix installer, conventional systemd user units,
RPM packaging, and COSMIC configuration merging. Its commit records a Fedora VM
trial but also an unfinished implementation: no COPR, launcher/monitor dependency
packaging, or greetd integration. That trial was not repeated in this audit. The
branch predates newer helpers such as Bluetooth authentication and tab restoration;
reuse the work after bringing its packaging and dependencies up to date.

Extraction steps:

1. Replace embedded `/run/current-system`, `/usr/local`, and `/usr` assumptions with
   package-provided paths and XDG lookup.
2. Define session units once and generate NixOS and conventional installations from
   shared definitions.
3. Move updates, Steam installation, hardware tuning, and personal-flake management
   behind OS-specific integration.
4. Expose backend capabilities for window management, capture, authentication, and
   updates. Unavailable services need useful fallback states.
5. Separate desktop defaults from the optional developer profile.

Distribution portability and compositor portability are separate projects. Keep
COSMIC as the first supported desktop backend. The current bridge relies on COSMIC
management protocols; additional compositors require explicit adapters and their
own compatibility tests.

## Animation and visual cohesion

Preserve the rail, connected cards, and drop animation as the visual foundation.
The review inspected animation code and the repository screenshot, but did not
measure frame pacing or assess a fresh recording of the complete shell.

- Repair the card geometry regression before tuning its easing.
- Make launcher timing state-driven. The fixed 300 ms reveal delay and 100 ms
  Vicinae polling coordinate separate windows through timing assumptions; align
  presentation with animation progress and launcher readiness.
- Reserve expressive motion for larger transitions. Try a quicker button
  compression with a softer release instead of the current 350 ms press animation.
  Treat timing changes as candidates for visual evaluation, not measured fixes.
- Share dialog framing, focus behaviour, spacing, and entry/exit motion across
  authentication, Wi-Fi, and Bluetooth prompts.
- Add reduced motion centrally, including `Drop`, authentication shaking, and
  direct animations outside `Anim.qml`.
- Profile the full-screen layers and shadow effects per output before adding blur.
  Measure GPU cost and frame pacing across supported resolutions and refresh rates.

## Remaining work for a complete desktop environment

The foundation includes window management, workspaces, notifications, locking,
polkit, audio, networking, Bluetooth, power profiles, screenshots, recording,
file management, and portals. Inheriting working COSMIC components is appropriate;
these recommendations do not require rewriting them.

| Area | Work to complete or validate |
|---|---|
| Settings ownership | One discoverable place for rail settings, primary monitor, motion, theme, and restore. COSMIC Panel/Dock pages are inert; Home Manager can move aside theme changes made through Settings. |
| Accessibility | Keyboard navigation, focus indicators, accessible names/actions, screen-reader validation, reduced motion, high contrast, and text scaling throughout custom controls. |
| Authentication and networking | General NetworkManager secret-agent handling for enterprise Wi-Fi/VPN and authentication conversations beyond repeatedly supplying one password. |
| Session reliability | Verified lock recovery, suspend/resume, output hotplug, service restarts, and clear degraded states. Critical functionality currently shares the shell process's failure domain. |
| Devices | Printing/scanning integration, removable/encrypted storage workflows, and firmware updates. GVfs already covers part of this. |
| Internationalization and input | Translatable strings, locale-aware conventions, IME integration, and keyboard-layout visibility during authentication. |
| Privacy and sharing | Camera and screen-sharing indicators, permission visibility, and verified portal stream teardown. The microphone indicator provides a starting point. |
| OS lifecycle | A supported application-installation path, understandable updates and rollback, recovery documentation, and automated install/upgrade testing. |

Give each setting and operation one owner. Primary-monitor policy currently spans
shell JSON, a greeter file, compositor configuration, and focus nudges. Theme policy
spans generated assets, COSMIC Settings, and Home Manager. Define how defaults,
user changes, and OS policy interact so those components agree.

the QML interactions or the new autoscroll state machine.

1. Fix and validate the identified defects, beginning with the compositor deadlock.
2. Document and deeply review the downstream patch stack, preserving AI provenance.
3. Establish shared session and configuration contracts.
4. Complete one non-NixOS desktop package and verify a full login session.
5. Finish accessibility and lifecycle integration.
6. Refine motion against visual evaluation and measured performance.
